## 根因分析

1. **测试模板复制**：18 个 `bpe-test/tests/test_XXX.rs` 为同一模板复制，仅 SQL 字符串、LOOP_SIZE、stream 列定义不同；`init_func/define_records/gen_u8_bytes/exec_with_time_it/fill_i64` 等辅助函数 100% 复制。
2. **测试/基准双份**：`bpe-core/tests/` 与 `bpe-core/benches/` 各自复制了辅助模块（bench_aux↔test_aux、bench_log↔test_log 整体重复）。
3. **示例与测试同构**：`bpe-sample/src/main.rs` 与测试文件共享 90% 结构。

## 改进建议

1. 抽取公共测试库：`bpe-test-utils` crate（define_records/gen_u8_bytes/exec_with_time_it/fill_i64）
2. 测试参数化：SQL/LOOP_SIZE 作为参数表驱动，而非复制文件
3. bench 与 test 共享辅助模块（如 `bpe-core/src/utest` 提升为公共 `test-utils`）
4. 将 bench_aux/bench_log 与 test_aux/test_log 合并为单一公共模块

## 结论

重复率 31.8%，**全部位于测试/基准脚手架**（生产代码本身重复度低）。属"测试组织方式"问题而非"业务逻辑复制"问题——修复成本低（抽取公共库），但对测试可维护性影响大（每次 SQL 变更需同步 18 个文件）。
