- **项目**：Bamboo Pipe Engine (BPE)，单表流式数据处理引擎（SQL + LLVM JIT）

- **规模**：bpe-core ~4150 行；测试/基准 ~5000 行；封装 ~600 行

## 重构目标

1. **正确性**：窗口扫描、聚合语义、多 mapper/多聚合全部正确
2. **安全性**：外部输入不再触发 panic/UB；release 不再可能 abort
3. **可验证性**：测试有断言，覆盖回绕/异常/多规则场景
4. **性能不回退**：热路径保持 JIT + 环形缓冲 + 零分配回调

## 重构策略

### 短期重构（Phase 1）：正确性修复

仅改核心算法与校验，不动架构。改动集中在 store.rs / mapper.rs / aggregate.rs / data.rs。

### 中期重构（Phase 2）：安全面收口

消除 UB 与 panic 面：聚合缓冲独立布局、错误传播、输入校验。

### 长期重构（Phase 3）：架构收敛

全局 static mut 收拢为受控状态对象；生命周期管理与资源释放；测试体系重构。

## 风险控制

### 重构风险

1. **性能回退**：修复窗口扫描（模运算迭代）可能增加每条记录开销 → 用 criterion 基准对比，目标 ≤10% 回退
2. **语义变更**：聚合从"累计"改为"窗口内"，影响现有调用方（sample/test 需同步）
3. **Phase 3 高影响**：全局状态收拢触及所有模块，建议独立分支 + 全量回归

### 回滚策略

- 按 Phase 提交，每 Phase 独立可回滚 commit
- Phase 1/2 为纯内部修复，不改公共 API（def_* / new_data 签名不变），可随时回滚

### 灰度策略

- Phase 1 完成即可发布（正确性修复，无 API 变更）
- Phase 3 收拢前保留 globalvar 兼容层，双状态并存一个版本

## 验收标准

1. 3000 条连续写入，LIMIT 10 回调 size 恒为 10（回绕正确性）
2. a=1,2,3 聚合：sum=6、count=3、avg=2（窗口语义）
3. 同 record 3 个 mapper 全部触发；3 个聚合分别绑定生效
4. 非法输入（未知列、超长 data_len、除零、stream 列不足）**不崩溃**，返回错误/None
5. 现有 18 个测试全绿且全部补断言；重复率 <5%
6. 基准：filter ~78ns、filter+agg ~156ns 目标值偏差 ≤10%
